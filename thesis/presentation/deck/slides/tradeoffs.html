PureSSM does the least work, but the gains come with real costs

Compute

Fewest operations (10.0 GFLOP) and the best accuracy per GFLOP (4.63).

But slowest in plain PyTorch (26.9 ms): many small operations. With CUDA graphs it runs at 181 Hz.

Memory

The Mamba models carry 144 MB of state per stream, 31× the baseline's 4.7 MB.

EventSSM is the fastest (12.6 ms, 0.44 J per frame) partly because it holds so much state.

Limits

One training run per model, so small differences are reported as ties.

50-ms windows set the latency (≈25 ms wait + compute), not the sensor. SSMs keep 62–70 % at 5 ms.

PureSSM does the least computation and has the best accuracy per GFLOP, but in plain PyTorch it is the slowest because it launches many small GPU operations; captured as a CUDA graph it reaches 181 Hz. The Mamba models keep 144 MB of streaming state per stream, 31 times the baseline: fast because fat. Limits: each model was trained once, so I treat small differences as ties; my models used batch 4 rather than 8; and the original micro-drone obstacle-avoidance aim was descoped so this could be a clean, controlled comparison. Latency: every model bins events into 50-ms windows, so detection waits about 25 ms on average for the window plus the compute time; the sensor's microsecond latency is not used at this setting. The window is a trade-off: with 5-ms windows and no retraining the SSMs keep 62 to 70 percent of their accuracy, PureSSM the most.
